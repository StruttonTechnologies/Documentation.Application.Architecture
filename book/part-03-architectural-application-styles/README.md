# Part 3 — Architectural Application Styles

The previous parts established the foundational concepts of software architecture and applied those concepts to the Strutton Technologies Application Architecture.

The next step is understanding how that architecture can support systems with different organizational and deployment needs.

Architecture is often confused with application style.

Clean monoliths, service-based systems, and microservices are frequently treated as entirely different architectures. In practice, they are different ways of organizing and deploying the same underlying architectural principles.

This part examines those differences without moving into implementation.

## In this part, you will learn

- how architecture differs from application organization and deployment
- how the same architectural model applies to clean monoliths, service-based systems, and microservices
- what remains consistent as a system changes style
- what changes as boundaries become more explicit and deployment becomes distributed
- how to choose the simplest style that satisfies the needs of the system

The goal is not to promote one application style over another.

The goal is to understand the trade-offs each style introduces while preserving the responsibilities, boundaries, contracts, and dependency rules established throughout the architecture.
