# Part I — Architectural Foundations

This part establishes the foundational principles that govern the Application Architecture
described in this book.

These principles define the *non-negotiable constraints* of the system. They are not
implementation details, framework choices, or stylistic preferences. Every architectural
element described later in the book assumes these foundations are in place.

---

## Purpose of This Part

The purpose of this part is to answer three fundamental questions:

- What problems is the architecture designed to solve?
- What constraints must all applications follow?
- What architectural rules are enforced rather than advisory?

By establishing these answers early, the remainder of the book can focus on structure and
intent without repeatedly re-justifying core decisions.

---

## Topics Covered

This part introduces the architectural foundations that shape the entire system, including:

- Boundaries and visibility rules
- Dependency direction and composition
- The role of contracts in enforcing architecture

These concepts form the basis for understanding the reference architecture and its
constituent sections.

---

## Reading Guidance

This part should be read sequentially. The sections build on one another and establish a
shared vocabulary that will be used throughout the rest of the book.
