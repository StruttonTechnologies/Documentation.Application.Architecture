# Architecture in Code

Architecture is not something that exists outside the codebase.

It is expressed through the code itself.

You can see it in how responsibilities are organized. You can see it in how architectural boundaries are maintained. You can see it in how dependencies flow between architectural units. You can see it in where business behavior lives and how different parts of the system interact.

If a system is difficult to understand, the architecture is unclear.

If a system is difficult to change, the architecture is no longer protecting the structure of the system.

There is no hidden layer where architecture exists.

It does not live only in diagrams, documentation, or presentations. It is reflected in every structural decision made throughout the codebase.

This is why architecture cannot be treated as something separate from implementation.

A well-designed architecture that is not reflected in the code is simply documentation. The architecture only becomes real when its principles are consistently applied throughout the implementation.

Every time a responsibility is assigned, every time a dependency is introduced, and every time an architectural boundary is respected or violated, the architecture is either being reinforced or gradually eroded.
