# Chapter 5 — What Changes and What Stays the Same

The previous chapters applied the architecture to clean monoliths, service-based systems, and microservices.

Because these styles look different operationally, they are often assumed to require fundamentally different architectures.

They do not.

The architectural principles remain consistent.

What changes is how responsibilities are grouped, how boundaries are represented, how communication occurs, and how the system is deployed and operated.

## In this chapter, you will learn

- which architectural principles remain constant across application styles
- what changes as boundaries become stronger or distributed
- why separating architecture from application style improves decision-making

This chapter brings the preceding styles together and identifies the distinction that must remain clear before choosing among them.
